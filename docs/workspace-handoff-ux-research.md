# Compact workspace handoff UX research

Research date: 2026-10-29. Scope: presentation of the existing operator-reconciliation gate; not permission changes or automatic reconciliation. Repository citations identify the owning implementation; recommendations below are design conclusions, not claims of exercised browser behavior.

## Recommendation: compact warning, available actions, disclosed evidence

Keep a compact, non-dismissible warning above the board: **Operator reconciliation required — new starts blocked.** Keep **Review & commit** and **Recheck workspace** outside the disclosure. Briefly expose the consequence of rechecking: **A clean recheck releases this project gate; eligible tickets may start under existing permissions.** This is consequential information, not optional troubleshooting. The runtime rejects eligibility while a handoff exists; the recheck confirmation already describes this exact consequence. The design language explicitly forbids hiding blocking errors or execution consequences for visual neatness. [Runtime eligibility](../server/runtime.ts#L118-L127), [handoff and confirmation](../src/Workspace.tsx#L123-L126), [feedback contract](design-language.md#L39).

Put the exact recorded reason, originating-run link when present, full escaped file list, and recovery steps under a native **Details** disclosure. Preserve the reason verbatim: a Git-inspection failure requires restoring access/Git, not merely committing changes. Preserve guidance to review partial work, protect unrelated edits, use an explicitly confirmed local commit or the terminal, and recheck only once clean outside `.omp-backlog/`. Collapsing explanatory material is a presentation change only; do not omit it. A file count can aid discovery but must not imply that zero recorded paths means clean: inspection failures create handoffs with an empty list. [Current handoff content](../src/Workspace.tsx#L123-L126), [inspection outcomes](../server/runtime.ts#L104-L115), [final-inspection failure](../server/runtime.ts#L236-L238).

Ant Design describes Alert as warning feedback and supports short messages, additional descriptions, and custom actions. That supports a concise warning/action composition, but does not require switching the existing panel to Alert or adopting a new dependency/API. The repository's existing notices, theme tokens, square surfaces, and Ant Design controls remain authoritative. Do not add a dismiss action that conceals a still-active gate. [Official Alert guidance](https://ant.design/components/alert/), [local component/feedback rules](design-language.md#L19-L39).

## Disclosure and keyboard semantics

Use one native `<details>` with its first child `<summary>Details</summary>`; place evidence and instructions after the summary. HTML defines this as a disclosure: the summary remains visible when `open` is absent, while additional content is hidden. No custom accordion, menu, or tabs are needed. [WHATWG details specification](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-details-element).

Preserve native focus and activation behavior, the disclosure marker or an equally clear expansion affordance, and visible keyboard focus. The WAI disclosure interaction model expects **Enter** and **Space** to toggle the focused control, and expanded/collapsed state to be exposed. For this native approach, let the browser own disclosure behavior rather than layering a separately managed ARIA button/state or custom key handlers over it. A custom alternative would need the WAI button/`aria-expanded` contract. Keep commit/recheck buttons separate from the summary, not embedded competing actions. [WAI disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), [native summary/open behavior](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-details-element), [repository focus contract](design-language.md#L74).

Retain the file list's `tabIndex={0}` when it needs keyboard scrolling and its `JSON.stringify` path rendering; an unescaped path list would lose the current explicit representation of unusual filenames. Do not treat disclosure as redaction: contents are still delivered to the client. The note needs no real repository paths, file contents, credentials, or session data. [Existing file rendering](../src/Workspace.tsx#L123), [existing scrollable diff readers](../src/WorkspaceCommit.tsx#L57-L59).

## Mobile actions and modal boundary

Wrap or stack warning, actions, and disclosure at narrow widths; preserve native control sizing and readable text instead of shrinking them to fit. Keep long file/path scrolling inside its reader, not the page. All actions and expanded recovery content must remain reachable on short screens. The commit workflow remains the existing modal, with body scrolling, explicit final confirmation, Back/cancel distinctions, and unsaved-draft protection; the compact handoff is not a replacement commit form. [Responsive contract](design-language.md#L64-L74), [operator modal design rule](design-language.md#L55), [draft protection and modal controls](../src/WorkspaceCommit.tsx#L26-L44), [confirmation stage](../src/WorkspaceCommit.tsx#L66-L69).

## Safety semantics that must not change

- **The gate concerns new starts, not ticket completion.** Human Done does not clear it; a commit does not mark tickets Done, release the queue, or itself start tickets. Keep the commit modal's warnings and receipt. [Runtime handoff reason](../server/runtime.ts#L193-L195), [commit warnings/receipt](../src/WorkspaceCommit.tsx#L45-L49), [final confirmation](../src/WorkspaceCommit.tsx#L66-L69).
- **Recheck inspects Git; it does not clean files.** Inspection reads porcelain status including untracked files and filters workspace metadata paths. Dirty or unavailable Git retains the gate; success removes the handoff and wakes the scheduler without changing execution mode. Preserve the explicit confirmation and “Keep blocked” cancel action. [Inspection/filter](../server/runtime.ts#L88-L115), [endpoint](../server/api.ts#L206-L222), [confirmation](../src/Workspace.tsx#L124-L125).
- **Existing concurrency/staleness guards remain.** The UI disables actions while busy or owned active work exists. The server checks the handoff identity and running/stopping/paused ownership before and after inspection. A stale review must not silently clear a newer gate. [UI action conditions](../src/Workspace.tsx#L123-L126), [endpoint guards](../server/api.ts#L209-L218).
- **Commit remains deliberate and local.** Preserve file selection, message, review/final confirmation, and warnings that reviewed working-tree versions replace selected staged versions while unselected staged changes are preserved. Preserve the terminal-review restrictions and the statement that filename/content screening is not a secret-scanner guarantee. Do not imply push, reset, stash, hooks, signing, clean filters, or automatic deletion. [Owning commit UI safety copy and flow](../src/WorkspaceCommit.tsx#L43-L69).

No checks, builds, linters, browser tests, commits, or workspace reconciliation were run for this research. Official live Ant Design documentation may describe a newer release; it is used here for design guidance, not installed-version API claims.
